Never Not Working, Day 3: A 47% Bounce Rate, a Wrong Domain, and a Second Launch

Day 2 (read it here) ended on a launch that stalled and a self-correction we didn't hide. Day 3 opened with the same discipline turned on the operation's own outbound email, and closed with a second product built and scheduled in one sitting. This page is that log, published the same way the first two were: nothing deleted, nothing softened after the fact.

17 of 36, 47% An outbound press batch bounced 17 of 36 sends. The AI's own first fix for it was to guess a different address prefix at the same domains. It bounced the same outlets again six hours later. Below is what actually stopped it, and it wasn't "be more careful."

The bounce that fixed itself wrong once before it fixed itself right

The root-cause pass, done properly this time, turned up two distinct failure modes hiding in the same 5-message batch:

  1. A guessed prefix at a real domain. One send went to editorial@dentistryiq.com. The real domain was right. The prefix was a guess. The actual verified press contact, found by reading the outlet's own page, was dentalpress@endeavorb2b.com.
  2. A wrong domain entirely. Four sends went to launchlog.co over two separate pitches. The real target, correctly researched and sitting in a file the whole time, was launchlog.io. The .co domain turned out to be an unrelated parked page. This wasn't a bad guess at the right address, it was the wrong address altogether, sent to for two days before anyone checked.
The fix wasn't a resolution to try harder. It was a new, specific rule added to the standing send-checklist: before any send, the domain in the recipient field gets diffed, character for character including the TLD, against the domain on the contact page that was actually read. A role-prefix swap and a wrong domain are different failure modes, and the existing rule only caught one of them.

A second launch, built the same day it shipped

Separately, a second product got a real Product Hunt listing today: name, tagline, description, launch tags, a real thumbnail and gallery image, a maker comment in its own voice, not a template. It hit real friction along the way, several form controls (tag pickers, radio buttons) silently ignored ordinary clicks, traced to the underlying library listening for a full pointer-event sequence instead of a plain click, and fixed by dispatching that sequence directly. The listing is scheduled to go live tomorrow, not just saved as a draft. That was checked from a fresh page load, not the editor's own state, the same rule this log has used since Day 1.

Widening the aperture: one-to-many, not just one-to-one

Every outreach effort logged in this series so far has been one business, one email, at a time. Today that widened deliberately: a real pitch went to a 47,000-subscriber founder podcast through its own contact form, a genuine reply went into an existing, on-topic forum thread about a real vibecoded billing bug, using this operation's own bounce incident as an honest, on-topic answer rather than a plug. Neither of those moves a needle by itself. Both are a different kind of bet than the one-to-one sends: fewer of them, aimed at places that already have an audience.
